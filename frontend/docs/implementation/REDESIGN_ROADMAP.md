# خارطة طريق إعادة بناء الواجهة (Redesign Roadmap)

**الهدف:** جعل KORA عملياً وسهل التنقل على غرار Basecamp: التنظيم حسب «المكان» (الفريق) وليس حسب «الميزة».
**الشكاوى التي نعالجها:** صعوبة الإنجاز، صعوبة إسناد المهام، صعوبة التنقل، عناصر مخفية، غياب التواصل.

## قواعد العمل

- **الباكند لا يتغير في المرحلة 1 و2 و3.** كل شيء يعتمد على الـ API الحالي (`API_CONTRACT.md`).
- لا نخترع قواعد عمل ولا نقاط نهاية. أي شيء يحتاج الباكند يُسجَّل في «المرحلة 5» ولا يُبنى وهمياً.
- لا روابط ميتة في القائمة (قاعدة موجودة في `nav.ts`).
- الصلاحيات تأتي من `/access/me` فقط؛ لا نفحص الألقاب.
- العربية/RTL هي الأساس، والإنجليزية تُحدَّث بنفس المفاتيح.
- بعد كل مرحلة: `npm run check` (lint + typecheck + test + build) يجب أن ينجح.

## المراحل

### المرحلة 0 — الأساس (هذه الوثيقة)
- [x] دراسة الواجهة الحالية والعقد.
- [x] تحديد السبب الجذري: قائمة علوية أيقوناتها بلا نص حتى المرور عليها، وصفحات عامة لكل ميزة بدل مساحة لكل فريق.

### المرحلة 1 — القشرة والتنقل (يعالج: التنقل، المخفي)
- [x] قائمة جانبية دائمة بنصوص ظاهرة دائماً على الشاشات الكبيرة.
- [x] أقسام: الرئيسية، فرقي (مولَّدة من `/access/me`)، التقويم/الإعلانات/الدوري، المتابعة، الإدارة (للمخوَّلين فقط).
- [x] الجوال: شريط سفلي بنصوص ظاهرة: الرئيسية، فرقي، التقويم، المزيد.
- [x] صفحة `/teams` تعرض فرق المستخدم.
- **معيار القبول:** كل صفحة قابلة للوصول بنقرة واحدة من القائمة، ولا نص مخفي.

### المرحلة 2 — الإنجاز والإسناد (يعالج: الإنجاز، الإسناد)
- [x] مكوّن `QuickAdd`: عنوان + مسؤول + موعد + Enter، ورابط «خيارات أكثر» يفتح النموذج الكامل الحالي.
- [x] مكوّن `TaskLine`: إنجاز المهمة بنقرة واحدة على الدائرة (مع احترام الانتقالات المسموحة).
- [x] الرئيسية الجديدة «ما عليّ اليوم»: متأخرة، هذا الأسبوع، بلا موعد، الفعاليات القادمة، آخر الإعلانات، عدد الإشعارات.
- **معيار القبول:** إنشاء مهمة مسندة في أقل من 5 ثوانٍ؛ إنجازها بنقرة.

### المرحلة 3 — صفحة الفريق (يعالج: كل شيء متفرق)
- [x] `/teams/:unitId` بتبويبات (في الرابط `?tab=`): المهام، التقويم، الإعلانات، الأعضاء.
- [x] تبويب المهام: إضافة سريعة + مجموعات (متأخرة / قادمة / بلا موعد / منجزة).
- [x] حماية الصفحة بصلاحية `task.view` على الوحدة.
- **معيار القبول:** مستخدم فريق واحد يرى كل ما يخص فريقه من صفحة واحدة.

### المرحلة 4 — التحقق والصقل
- [x] اختبارات للرئيسية الجديدة وصفحة الفريق والإضافة السريعة (`tasks.test.tsx`)؛ `npm run check` ينجح.
- [ ] فحص بصري على الجوال والشاشة الكبيرة وRTL/LTR.
- [ ] تحديث `frontend_PROJECT_STATE.md`.

### المرحلة 5 — التواصل (تحتاج قرارات + باكند؛ لا تبدأ قبل الاتفاق)
قرارات مطلوبة منكم:
1. من يراسل من؟ (أي عضو لأي عضو، أم داخل الفريق/الإدارة فقط؟)
2. هل يوجد نقاش للفريق (قناة) بالإضافة إلى الرسائل المباشرة؟
3. هل تُحفظ الرسائل للتدقيق أم تُعامل كمراسلة خاصة؟ (سجل التدقيق عندكم يمنع تخزين نصوص التعليقات)
4. هل تُرسل إشعاراً لكل رسالة؟

ثم: باكند (`messaging` domain: نماذج + migration + صلاحيات + اختبارات) ثم واجهة (تبويب «النقاش» في الفريق + صندوق «الرسائل»).
